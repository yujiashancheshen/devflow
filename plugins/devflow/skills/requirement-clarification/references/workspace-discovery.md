# 工作区与代码定位

## 工作区规则

- 当前执行目录是工作区，可以包含一个或多个 Git 仓库、需求材料和符号链接。
- 用户未指定其他位置时，只在当前工作区内搜索，不根据 PRD 路径猜测工作区外目录。
- 当前目录不是 Git 仓库，不代表缺少代码；必须继续检查直接子目录和符号链接。
- 无法使用 Git worktree 不影响当前阶段的只读代码搜索。

## 定位步骤

1. 列出工作区根目录的真实目录和符号链接。
2. 对可读链接使用 `readlink` 解析目标，检查 `.git`、`go.mod`、`package.json` 等项目标识。
3. 从 PRD 提取系统名、模块名、接口名、页面名和业务术语。
4. 在候选模块中搜索文件名和内容。符号链接使用 `rg --follow`、`find -L` 或解析后的真实路径。
5. 排除 `.git`、`node_modules`、`vendor` 和构建产物。
6. 至少定位到相关入口、数据结构或核心业务逻辑，才算完成代码库确认。

仅找到任意 Git 仓库、源码目录或同名文件，不算已经定位相关代码。

## 定位失败

找到多个候选仓库但无法判断范围时，使用当前环境的交互式询问工具列出候选位置，请用户确认。

完成根目录盘点、符号链接检查和关键词搜索后仍找不到相关代码时，请用户提供相关前端、后端、公共组件或上下游仓库路径，然后暂停。运行环境有交互式询问工具时优先使用；没有时退化为普通文本询问。

代码定位失败属于执行阻断，不是 PRD 业务问题。不得写入问题列表，也不得用“仅文档审查”代替正式需求澄清。

用户提供路径后，确认路径存在且可读，并实际搜索与 PRD 对应的入口、数据结构和业务逻辑。仍无法定位时继续询问模块或目录范围。

## 路径记录

问题列表中的文件路径统一写为 `<Git 仓库目录名>/<仓库内相对路径>`。涉及多个仓库时分别使用各自仓库名。不在 Git 仓库中的材料使用相对最终产物的路径，并标注“仓库外材料”。

不得把用户额外提供的代码路径写入 `flow-state.json` 的未定义字段。
