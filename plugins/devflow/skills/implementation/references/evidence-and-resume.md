# 证据与续跑

在已有 `plan.md`、`test-report.md` 或 `review-report.md`，或实施中断后恢复时读取。

## 轻量标识

只维护以下标识：

- `design.md` 内容指纹。
- 递增的计划修订号。
- 记录验证时的最终 HEAD。
- 覆盖已跟踪差异与未跟踪文件内容的工作区指纹。

工作区指纹使用 `scripts/worktree_fingerprint.sh <仓库路径>`。时间戳、文件清单和 `git diff --check` 不能替代内容指纹。

## 恢复规则

1. 读取最新设计、三份实施产物、Git diff 和工作区状态。
2. 重新计算 design、HEAD 和工作区指纹，不覆盖或还原用户修改。
3. design 指纹或计划修订号变化时，重新判断受影响任务，未受影响证据可以保留。
4. 最终 HEAD 或工作区指纹变化时，旧测试与 Review 结论失效；只重跑受影响验证，收口前仍执行仓库适用的整体检查。
5. 计划标记完成但代码或报告没有当前证据时，将任务恢复为进行中。

## 变化处理

计划可以直接调整任务拆分、同一设计边界内的目标文件、执行顺序和验证命令。

以下变化必须暂停受影响任务并返回详细设计：

- 需求范围、仓库职责、页面或路由落点变化。
- API、消息、数据字段、错误或兼容契约变化。
- 状态归属、核心交互、验收场景或允许实施范围变化。
- 设计与工程知识库冲突，或真实代码变化使设计无法成立。

聊天记录和临时口头结论不能直接替代 `design.md`。
