# 错误与资源

所有后端审查都应用本文件。

- 检查 error 是否被忽略、覆盖、返回错变量，或记录后继续使用无效结果。
- 错误封装必须保留调用方需要识别的 sentinel、错误码或 `errors.Is/As` 语义。
- 只在当前路径确实可能为空时要求 nil 检查；同时检查索引、类型断言、除零、溢出和单位转换。
- 文件、HTTP body、Rows、事务、压缩流、timer 和 ticker 应在所有可达退出路径释放。
- 循环内 defer 不得导致资源无界延迟释放；Rows 按驱动和调用方式检查 `rows.Err()`。
- cleanup 错误是否返回取决于数据完整性和调用契约，不机械要求所有 `Close()` 覆盖主错误。
- 日志与错误处理遵循仓库知识库和既有 helper，不在多层重复记录同一错误。
