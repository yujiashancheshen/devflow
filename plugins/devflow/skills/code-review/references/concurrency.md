# 并发与生命周期

只在当前改动引入或改变并发行为时应用本文件。

## Goroutine 与 Channel

- goroutine 应有与职责匹配的结束条件；循环启动时检查并发上限、积压、错误收集和调用方返回后的生命周期。
- 无缓冲 channel 必须存在可并发执行的对端；持续接收需要可证明的退出路径。
- 不机械要求所有 channel 关闭或所有 goroutine 独立监听 `ctx.Done()`，只报告可达的阻塞、泄漏、重复关闭或关闭后发送。

## 锁与共享状态

- 检查所有退出路径的 Lock/Unlock 配对和多把锁的获取顺序。
- `sync.Mutex`、`sync.RWMutex`、`sync.Once` 首次使用后不得按值复制。
- map 并发写、slice 并发 append 和共享字段读写需要明确同步或所有权。
- 不因包级变量存在就报告，必须证明运行期存在未同步的并发读写。

## Context 与版本

- 请求链路中的阻塞 IO 应传播 context，并尊重取消和超时。
- 后台任务使用独立 context 必须符合生命周期设计。
- 先读取 `go.mod`；Go 1.22 及以上不报告标准 `for range` 循环变量捕获问题。
