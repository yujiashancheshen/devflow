# 前端代码核对与概要设计边界

## 目标

用真实前端代码确认运行端、仓库职责、页面归属、共享能力和跨仓影响，只把会影响方案边界、职责划分、评审和排期的结论写入概要设计。组件内部实现、样式参数和测试细节留给后续详细设计。

## 事实源与代码基线

仓库导览、前端方案规范和 UI 规范用于缩小搜索范围，不能代替当前代码。判断现状时按以下顺序取证：

1. 目标仓库当前需求分支的代码。
2. 宿主注册、路由或页面注册、构建配置和运行入口。
3. 页面、共享组件接入层、API、store、hooks/composables 和跨仓调用点。
4. 仓库导览、历史设计和规范文档。
5. PRD、原型和 UI 只用于说明目标，不用于证明当前实现。

概要设计使用用户确认的当前代码基线；完整流程中的需求分支在概要设计确认后由开发分支准备 Gate 统一创建或切换。执行本 skill 时：

- 只读取目标仓库当前基线分支，不主动创建、切换或重置分支。
- 记录每个前端仓库的 Git 根目录、当前分支、commit、工作区状态和核对范围。
- 多仓需求逐仓记录，不能用一个 commit 代表全部前端 Git 仓库。
- 发现相关未提交修改时按工作区版本核对并注明，不覆盖或还原。
- 当前基线分支用途不明或代码正在迁移时，标记 `待确认`。

在 `3.1 页面变更` 中先记录：

| Git 仓库 | Git 根目录 | 分支 | Commit/工作区 | 端/应用形态 | 核对范围 | 结论 |
|---|---|---|---|---|---|---|

`Git 仓库` 填写 Git 根目录名；页面、组件和应用形态只用于说明仓库内职责，不得作为模块名。

## 端类型与应用形态

先确认真实运行入口，再判断页面落点。仓库名称只能辅助判断，不能作为结论。

| 端/形态 | 必查证据 | 概要设计要回答 |
|---|---|---|
| Qiankun 宿主 | 子应用注册、菜单/路由壳、全局注入、页面容器 | 是否只改宿主入口、装载或全局能力 |
| Qiankun 业务子应用 | bootstrap/mount、active rule、子应用路由、宿主共享接入层 | 由哪个子应用承载业务内容 |
| 独立 PC SPA | 独立入口、路由和部署配置 | 是否与 Qiankun 完全独立，不能假设宿主注入 |
| H5 | 路由、入口渠道、登录态和容器桥接 | 普通浏览器、企微还是 hybrid 环境 |
| 小程序原生页 | app/page 配置、主包/分包和页面注册 | 目标页面属于哪个小程序与分包 |
| Webview/容器页 | URL 组装、参数透传、跳转和返回逻辑 | 当前仓只承载容器，还是同时承载内容 |

名称带 `-sys` 不等于一定属于 Qiankun；名称带 `-mini` 或 `-h5` 也不能证明真实内容就在该仓。必须区分：

- `内容页`：承载展示、录入和提交等业务主体。
- `容器页`：负责装载、webview、参数透传或路由壳。
- `联动页`：负责入口或跳转，主体内容由其他仓承载。

## 仓库职责与页面归属

按以下顺序确定主仓和联动仓：

1. 明确目标用户、终端和入口渠道。
2. 从仓库导览获得候选仓，不直接定稿。
3. 核对候选仓的运行入口、路由、相似页面和业务区域。
4. 判断当前仓承载内容、容器还是联动职责。
5. 沿 URL、路由、宿主注册、共享组件和接口调用查找联动仓。
6. 为每个仓写清职责、输入输出和改动类型。

以下情况属于概要设计阻断项：

- 两个候选仓都能承载主页面，无法确认主责。
- 无法确认内容页与容器页分别位于哪个仓。
- 多仓之间的参数组装、状态透传或跳转职责不明确。
- 不清楚能力属于业务仓、宿主还是共享仓。

## 共享能力判断

概要设计只确定共享边界和责任方，不设计 Props、Events 或内部实现。

按以下层级判断：

1. 页面私有能力：只服务当前页面，留在页面边界内。
2. 仓内公共能力：同仓多个稳定场景复用，由当前业务仓负责。
3. 宿主共享骨架：列表页、表单页、弹窗、页面容器等结构性能力，优先使用目标仓已经接入的宿主能力。
4. 跨仓共享业务能力：多个业务子应用复用，评估由共享仓负责，并列出消费方。

必须核对目标仓的真实接入方式。若规范分别声明 npm 包、宿主注入、`share.components` 或远程组件入口，不擅自选择；沿 import、宿主注入和运行代码确认实际生效方式。无法确认时记录冲突。

共享能力发生修改时，概要设计至少写清：

- 能力所有者和修改仓库。
- 当前消费仓或代表性消费页面。
- 是否改变公共契约、默认行为或视觉契约。
- 需要联动适配和回归的范围。
- 旧消费方是否兼容以及上线顺序是否受约束。

## 跨仓影响判断

出现以下信号时继续追踪，不能只记录当前页面：

- 宿主菜单、子应用注册、共享资源注入或统一主题发生变化。
- 小程序通过 webview 打开 H5，或 H5 依赖容器参数、桥接和登录态。
- 配置后台修改字段、规则或状态后由其他端消费。
- 共享组件、共享 hooks、远程组件或公共页面骨架发生变化。
- 全局样式、Element 主题、Teleport 挂载或 z-index 可能越过子应用边界。

概要设计按仓记录 `主责`、`联动`、`共享能力消费方` 或 `无代码改动但需回归`，并说明依赖方向。不要把多仓职责混写成一个笼统的“前端修改”。

## 概要级组件边界

`3.2 页面详情` 只记录影响架构和复用决策的组件或能力：

| 页面/能力 | 边界层级 | 决策 | 目标组件/共享能力 | 概要职责 | 依据/例外 |
|---|---|---|---|---|---|

- `边界层级`：页面私有、仓内公共、宿主共享骨架、跨仓共享。
- `决策`：新增、修改、复用、待确认。
- 只列页面容器、稳定业务区块和共享能力，不逐个统计 `.vue` 文件。
- 不输出完整目标目录树、组件内部层级、Props、Events、slots、store、hooks/composables、接口映射或伪代码。
- “两个页面看起来相似”不足以支持公共化；业务耦合度或结构稳定性不明时写 `待确认`。

## UI 规范边界

概要设计只记录：

| 页面 | 所属 Git 仓库 | 适用规范 | 标准骨架 | 合理例外 | 原因与影响范围 |
|---|---|---|---|---|---|

- 适用的 UI 规范名称或版本。
- 复用的列表、表单、弹窗或页面容器骨架。
- 是否需要修改宿主主题、共享视觉契约或跨应用样式边界。
- 无法使用标准骨架时的业务理由、责任方和影响范围。

不要在 `概要设计文档.md` 复制具体色值、字号、行高、圆角、间距、控件尺寸、CSS Token、状态矩阵、响应式断点、动效参数、可访问性检查项或视觉回归步骤。这些由详细设计引用对应规范并落到实现与验收。

全局样式、Teleport 和 z-index 只有在改变宿主/子应用边界、共享能力或影响多个消费方时进入概要设计；具体选择器、挂载点和层级数值留给详细设计。

## 一致性检查

完成前端章节后确认：

1. 每个页面都能对应到真实端、仓库、应用形态、入口或路由证据。
2. 主仓、联动仓及内容页/容器页职责没有互相遗漏。
3. 共享能力的所有者、接入方式和消费影响来自代码而不是规范猜测。
4. 页面变更、概要级组件边界、影响范围和上线依赖互相一致。
5. UI 章节只有规范、共享骨架和例外，没有落入详细参数。
6. 未确认的仓库归属、共享责任或跨仓契约已进入待确认事项。
