# 前端详细设计规则

## 代码事实

核对真实路由、页面入口、容器挂载、组件树、API 封装、类型、store、hooks/composables、样式体系和已有测试。复用结论必须落到具体路径、symbol、注册名或真实消费方。

## 页面与文件落点

- 逐页说明页面角色、路由或入口、目标文件和新增、修改、复用或删除决策。
- 组件只拆到独立业务行为、稳定复用边界或视觉职责，不为每个 DOM 节点建立契约。
- 写清 Props、Events、Slots、状态所有者、API/Hook 依赖和共享组件兼容范围中的适用项。

## 状态与数据流

- 覆盖 Loading、Empty、Error、Disabled、Permission 和容器异常中的适用状态。
- 写清请求参数如何由页面、URL、Tab、筛选和分页组成，响应字段如何映射到视图状态。
- 明确并发、去重、取消、缓存、刷新、返回页面恢复和错误展示策略。
- B 端列表按需说明筛选、Tab、列、操作、分页、URL 状态和生命周期，不生成空矩阵。

## 接口消费

按照契约展开规则生成可直接定义前端类型的完整最终请求和响应。记录接口所有者、实现就绪度、字段来源与转换、可空性、枚举、错误、兼容和敏感信息处理。

前端代码用于确认当前封装和消费事实，后端代码用于核对当前提供能力，概要设计提供目标变化。三者冲突时阻断受影响页面，不静默选择其中一方。

## UI 与视觉

- 有 UI 变化时记录设计源、适用页面和状态、目标视口或容器、项目组件与 Token 复用方案。
- 项目已经配置设计转换或视觉检测工具时，记录实际工具、版本、输入、运行方式、产物路径和通过条件。
- 不假设固定存在 MasterGo、VOM 或特定 Skill；工具不可用时只阻断依赖它的视觉范围。
- 视觉实现通常先用稳定 mock 完成页面状态，再接业务逻辑；逻辑改变布局后复检受影响区域。
- 不在文档中记录 cookie、token、账号或其他秘密。

## 测试重点

默认验证页面行为、状态变化、接口映射、异常态、权限、容器边界和关键视觉回归。纯函数或复杂状态计算按风险增加单元测试，跨仓连续流程留给 E2E。
