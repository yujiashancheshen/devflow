# 契约展开规则

## 目标

详细设计必须提供实施所需的完整最终契约，但不能要求概要设计重复保存字段全集。

## 展开方法

1. 从目标分支真实代码读取当前完整定义，包括统一信封、DTO、枚举、校验、序列化和调用方假设。
2. 从概要设计读取已确认的新增、修改、删除、兼容策略和责任方。
3. 合并为实施后的完整定义，并标注每项是保留、新增、修改还是删除。
4. 核对提供方和消费方对字段、类型、必填性、可空性、默认值、枚举语义和错误行为的理解。

对于全新契约，使用 PRD、概要设计、已确认问题结论和工程规范补齐完整定义。关键内容仍不足时阻断，不用“待实现”掩盖契约缺失。

## HTTP 与 RPC

- 记录所有者、调用方、METHOD/方法、PATH/服务、鉴权或调用身份。
- 完整列出最终请求和响应，包括统一信封、嵌套字段、数组元素、类型、必填或可空、默认值和枚举。
- 写清参数来源、字段计算、错误映射、超时和兼容行为。
- 已有接口说明代码证据；新增接口说明目标文件和注册位置。

## MQ 与任务

- MQ 记录 Topic/Tag、生产者、消费者、完整最终消息体、触发条件、幂等键、顺序要求、失败分类和补偿方向。
- 定时或一次性任务记录入口、调度方式、处理范围、游标或分页、状态变化、重入、失败恢复和可观测结果。
- 精确并发、批量、重试和告警参数只有在平台约束或证据明确时固定；否则作为待压测或配置项。

## 配置与持久化结构

- 数据库记录最终表或字段定义、索引、约束、默认值、迁移方式和旧数据处理。
- 配置、JSON、缓存或第三方协议记录版本、读写方、默认行为、缺失 fallback 和回滚读取能力。

## 冲突处理

- 代码现状与概要变化可以合并：在详细设计中完成展开。
- 提供方与消费方现状不一致：记录双方证据并阻断受影响契约。
- 概要变化会改变仓库职责、责任方或兼容策略：回到概要设计确认。
- 纯仓内实现选择不改变对外契约：在详细设计中按工程规范裁决。
