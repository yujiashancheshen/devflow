# 后端详细设计规则

## 代码事实

沿真实调用链核对路由或入口、Handler/Controller、Service/Domain、模型与 DTO、数据库或外部依赖。记录当前分支、commit、目标文件和关键 symbol。

不要预设 Gin、固定 Command 生命周期、固定 ID 类型、固定目录或任务框架。以目标仓库现有结构和工程知识库为准。

## 文件与职责

列出所有需要新增、修改或删除的生产代码、迁移、配置和测试文件。每项说明当前职责、目标变化、调用关系和依据。只列目录不足以驱动实施。

## 数据与领域

- 明确领域不变量、状态变化、校验位置和数据所有权。
- 涉及数据库时给出最终字段、约束、索引和迁移策略；完整 SQL 仅在团队规范要求设计阶段确定时提供。
- 明确事务边界、锁或并发策略、幂等结果、部分失败和补偿。
- 说明新代码读取旧数据、回滚代码读取新数据时的行为。

## 入口程序

- HTTP/RPC 写清路由注册、绑定校验、领域调用、响应转换和错误映射。
- MQ 写清生产或消费入口、序列化、幂等、事务关系、重试耗尽和人工补偿。
- 定时或一次性任务写清调度入口、扫描条件、处理窗口、状态推进、重入、积压和监控。
- 资源操作写清超时、取消、连接或锁释放以及降级行为。

## 实现粒度

关键逻辑应说明执行顺序、分支、不变量、读写点和外部调用，但不需要把设计写成完整可编译代码。只有签名、类型或结构本身属于稳定实现契约时才给出代码草图。

## 测试重点

优先从真实入口验证业务结果。复杂纯逻辑、状态计算、解析器和缺陷修复补充单元测试；事务、消息和跨服务行为按风险选择集成或 E2E。
